# 操作手感与输入延迟验收

本次目标是让单人输入脱离服务器往返，并让合作模式在按键发生时立即显示本机运动。不是 NES 模拟器；未取得相同 ROM、显示与输入设备的逐帧比较证据。

## 来源与接入

固定 FullScreenMario 版本 `dc7db1fdea151684d78425bd1152ff680c7047d6`。

| 行为 | 固定源代码 | 本项目与结果 |
| --- | --- | --- |
| 起步、跑步、松键减速、反向刹车 | settings/math.js 的 decreasePlayerRunningXvel；objects.js 的 maxspeed 与 movePlayer 的蹲下尺寸 | shared/motion.mjs；源速度乘30换算为 px/s，跑速上限162，蹲下高度22px，反向输入先刹车再转身 |
| 可变跳高、游泳 | decreasePlayerJumpingYvel、jumpmod、gravity / 2.8 | 复用原批次跳跃公式，单人与合作预测共用同一运动函数 |
| 奔跑、刹车像素 | settings/sprites.js 的 running/skidding，animatePlayerRunningCycle 的帧间隔 | 源 RLE/调色板生成三种形态刹车素材，奔跑动画间隔随速度变化 |
| 碰撞 | 现有网页实体与地图几何 | 按前一帧边界判断穿越，修复从侧面触碰平台却被吸到顶面的错误；该碰撞器属于移植实现 |

`scripts/import-controls-reference.mjs`直接执行固定源 math.js，生成独立速度轨迹与源文件哈希，记录在 `controls-reference-2026-11-24.json`。五条轨迹覆盖走路、跑步后松键、反向刹车、水下禁用疾跑、蹲下减速；实现与轨迹误差小于1e-10 px/s。不是以实现自己生成期望值。

## 运行路径

单人连续闯关使用打包后的 `MarioRuntime.createLocalGame`，世界、敌人、碰撞、奖励、死亡与过场均在浏览器60Hz计算，不建服务端房间。P / Esc 与按钮暂停，窗口失焦或进入后台自动暂停，返回后明确继续；恢复时不补算后台经过的时间。资源仍需首次从OSS加载，本次没有增加离线缓存安装能力。

合作模式使用版本2按键帧协议，每秒60次采样，通常每2帧合并发送；服务端每个模拟帧最多消费一个输入，不接受客户端坐标或时间推进。每秒20次返回权威快照、已处理序号及本人运动状态；客户端重放尚未确认的按键。本人直接显示预测位置，小幅校正平滑收敛，其他玩家保留插值。死亡、变身、传送、爬藤与过场切换以服务端状态为准；道具、敌人、伤害、计分和通关不由客户端预测决定。

预测最多24条待确认按键、无回包最多300ms；服务端400ms未收到输入后释放按键，队列有上限。预测跳跃声立即播放，并按按键序号去除权威事件的重复声。

## 验收证据

- 54项测试通过，包含源速度轨迹、阶梯侧面碰撞、跳跃顶头、蹲下尺寸、短按/松开分帧、输入队列上限、断线与重连、传送/死亡/过场预测重置。
- 200ms往返延迟模拟中，角色在首个回包前已经移动，待确认队列10–16帧，所测走跑/反向/跳跃过程单次校正小于3px，停止后与权威状态差小于0.1px。此为可重复的网络模拟，不宣称所有公网环境均有相同误差。
- 浏览器格式 bundle 在无 Node API、禁止 fetch/WebSocket 的环境运行，5个代表关卡各480帧与服务端快照逐帧相同，无游戏状态网络请求。
- 10条代表关卡输入路线按新惯性重新生成，并从正常出生点回放，全部3条命完成；包括4-4、7-4迷宫及8-4全部5个区域与公主结局。见 `verification-controls-campaign-2026-11-24.json`；输入回放未写坐标、生命或完成状态。
- Safari 本地正式入口实测单人启动、方向键移动、空格跳跃、P暂停；画面显示“单人 · 本地运行”，暂停时角色停在空中。此时健康接口 rooms=0、players=0。

公网发布为 `20261124-controls-v2`，212个OSS文件共12,652,256字节全部通过哈希与CORS验证，音频Range返回206。公网4客户端通过版本2输入确认、同地图/快照、移动、4人上限和断线重连；Safari实际2人合作房间验证移动与跳跃。单人正式入口和P暂停、后台自动暂停及继续也通过浏览器操作检查。验收结束已退出测试房间，在线人数恢复0。见 `verification-controls-release-2026-11-24.json` 和 `verification-oss-controls-2026-11-24.json`。

联网条件变化、移动设备浏览器帧率、合作平台其他乘员和服务端碰撞结果可能触发位置校正。当前结论是源运动公式已接入并完成代表验证，不是 NES 原机完全一致。
